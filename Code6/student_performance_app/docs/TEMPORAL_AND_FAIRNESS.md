# Temporal Validation and Fairness Disaggregation

Two questions a single accuracy figure cannot answer, and how this system
answers them.

Version 3.3 · All numbers below are from the **synthetic** cohort generated by
`scripts/make_synthetic_dataset.py --rows 2000` (seed 42). Nothing here
describes real students.

---

## 1. Why these two analyses exist

A model reported as "64% accurate" has told you almost nothing you need to know
before it influences a decision about a person. Two follow-up questions matter:

| Question | Analysis | Module |
|---|---|---|
| Does it still work next semester? | Temporal validation | `backend/preprocessing/split_strategy.py` |
| Does it work equally well for every group of students? | Fairness disaggregation | `backend/evaluation/fairness.py` |

The first guards against a **random split** that lets the model see the future
it is meant to predict: rows from the same semester share cohort effects (same
lecturer, same timetable, same marking scale), so a random 80/20 split measures
fit, not transfer.

The second guards against an **average** that hides the students the system is
most likely to harm. A model can be 65% accurate overall and 42% accurate for
one programme, and the average will never mention it.

---

## 2. Temporal validation

### How

```
train: 2024/25-S1 + 2024/25-S2   →  test: 2025/26-S1
```

* The period column is auto-detected (`semester`, `session`, `term`,
  `academic_year`, `academic_period`, `cohort`, `period`) or named explicitly.
* The default held-out period is the **most recent** one in the data.
* Periods are never split across both sides — that is the whole point, and it is
  asserted on row indices, not just labels.
* Refusals are explicit rather than silent: a missing period column, an unknown
  period name, fewer than 50 training rows, fewer than 20 test rows, or a single
  class on either side all raise a message that says what to do. A silent
  fallback to a random split would produce a temporal *claim* that never
  happened.

### Run it

```bash
python scripts/train_model.py --data data/cohort.csv \
    --split temporal --out models/best_model.pkl

python scripts/report_results.py --data data/cohort.csv --temporal \
    --out reports/results.md          # trains twice: random and temporal
```

### Result on the synthetic cohort

Hold-out = 2025/26-S1 (490 rows), training = 1510 rows.

| Model | Random split | Temporal split | Change |
|---|---|---|---|
| Soft-Voting Ensemble | 0.649 | 0.655 | +0.006 |
| Random Forest (Tuned) | 0.640 | 0.648 | +0.008 |
| Random Forest (Calibrated) | 0.643 | 0.651 | +0.008 |
| Logistic Regression (Calibrated) | 0.613 | 0.622 | +0.009 |
| Random Forest | 0.631 | 0.640 | +0.009 |
| Logistic Regression | 0.625 | 0.652 | +0.027 |

Macro F1 throughout.

### What that result does and does not mean

**It does not mean** the model is time-robust in the real world. The generator
injects a semester effect that is a plain additive shift (+1.5 marks on the exam
for 2025/26-S1). An additive shift preserves the *relative* signal structure, so
a model trained on earlier periods transfers almost perfectly. Real cohort
effects are not additive: the exam changes what it measures, the marking scheme
changes systematically, the intake changes. That is the case this synthetic
cohort cannot reproduce, and the honest reading of the table above is
"no degradation under a benign shift", not "robust across semesters".

**It does mean** the machinery is correct and the number is now producible: on
your real multi-semester export the same command reports the actual change, and
a negative change of any size is a finding you must report rather than discover
at deployment.

## 3. Fairness disaggregation

### How

For each demographic column present in the data (checked aliases: `gender`,
`sex`, `programme`, `program`, `course`, `department`, `entry_qualification`,
`entry_mode`, `level`), the held-out predictions are grouped and reported with:

| Column | What it answers |
|---|---|
| n | How much the row is worth |
| Accuracy, macro F1 | How well it does for that group |
| Recall per class (Low / Average / High) | **Who gets missed** |
| Predicted distribution | **Who never gets flagged** |
| Flags | Small support, or a class the model never predicts for that group |

Three honesty rules are built into the code rather than left to the reader:

1. **Small subgroups are marked unreliable, never averaged in.** Below
   `min_support` (default 30) a row is labelled and excluded from the gap.
2. **A single reliable subgroup yields no conclusion.** The summary says so
   instead of reporting a tidy 0.000 gap.
3. **Nothing is "corrected".** Detecting a disparity is the job here; deciding
   what to do about it belongs to the institution, and a re-weighting trick in
   the evaluator would hide that decision.

### Result on the synthetic cohort

The generator assigns programme and gender at random, with one documented
structural effect (a programme attendance offset). So the gaps below are small,
and they are small **by construction** — this is what a fairness table looks
like when there is no bias to find, which is a useful baseline to compare your
real data against.

**By gender** (hold-out n = 490)

| Subgroup | n | Accuracy | Macro F1 | Recall Low | Recall Average | Recall High |
|---|---|---|---|---|---|---|
| Female | 246 | 0.691 | 0.686 | 0.861 | 0.532 | 0.678 |
| Male | 244 | 0.615 | 0.621 | 0.765 | 0.534 | 0.580 |

Gap in macro F1: **0.065** (Female 0.686 vs Male 0.621).

**By programme**

| Subgroup | n | Accuracy | Macro F1 | Recall Low | Recall Average | Recall High |
|---|---|---|---|---|---|---|
| BSc Information Technology | 173 | 0.670 | 0.673 | 0.711 | 0.600 | 0.714 |
| BSc Computer Science | 161 | 0.665 | 0.656 | 0.877 | 0.500 | 0.596 |
| BSc Information Systems | 156 | 0.622 | 0.620 | 0.844 | 0.479 | 0.571 |

Gap in macro F1: **0.053** (IT 0.673 vs IS 0.620).

**By entry qualification**

| Subgroup | n | Accuracy | Macro F1 | Recall Low | Recall Average | Recall High | Flags |
|---|---|---|---|---|---|---|---|
| WASSCE | 327 | 0.639 | 0.639 | 0.796 | 0.520 | 0.621 | — |
| Diploma | 90 | 0.633 | 0.639 | 0.724 | 0.562 | 0.621 | — |
| Mature | 44 | 0.682 | 0.685 | 1.000 | 0.522 | 0.700 | — |
| Transfer | 29 | 0.828 | 0.801 | 1.000 | 0.625 | 0.714 | **unreliable (n < 30)** |

Note the Transfer row: it looks the *best* of the four and is therefore the most
dangerous line in the table, because n = 29 students. It is flagged, excluded
from the gap, and must not be quoted as evidence that the model favours transfer
students.

### The number that recurs

Across all three columns, recall for **Average** is 0.48–0.63 — consistently the
weakest class, in every subgroup. That is the same finding as the per-class table
in the main results: borderline students are where the model is least reliable,
and a borderline student is exactly the one an early-warning flag would be acted
on. It is a property of the model and the labels, not of any one group.

## 4. What to do with this on your real data

1. Make sure the export carries the columns: `semester` (or `academic_year`) and
   at least one of `gender`, `programme`, `entry_qualification`. Without them
   both analyses are impossible and the reports will say so explicitly rather
   than quietly omitting the section.
2. Run both:

   ```bash
   python scripts/report_results.py --data data/real_cohort.csv --temporal \
       --out reports/results.md --json reports/results.json
   python scripts/train_model.py --data data/real_cohort.csv --split temporal \
       --fairness --out models/best_model.pkl
   ```

3. Report the temporal change **and** the fairness gap next to the headline
   accuracy, not in an appendix. A single number without either is the kind of
   claim this project exists to avoid.
4. If a subgroup is below 30 students, report the row and the reason it is
   unreliable. Do not merge it into "Other" to make the table tidy — merging is
   itself an analytical decision that needs justifying.

## 5. Tests that hold these claims in place

`tests/test_temporal_and_fairness.py` (24 tests) encodes the properties that
make the two analyses trustworthy:

* no period appears on both sides of a temporal split (checked on row indices);
* a test period smaller than the minimum is refused, not silently used;
* a single class on the test side produces a warning;
* the pipeline defaults to a random split, so nothing changes silently;
* perfect predictions produce a zero gap;
* a 100%-vs-0% split between two groups is reported as a 1.0 gap, not as a
  67% average;
* a subgroup of 20 is flagged unreliable and cannot set the gap;
* a class the model never predicts for a group is named in the flags;
* misaligned inputs raise instead of producing a plausible-looking table.

Full suite: **86 tests**, `python -m pytest tests -q`.
